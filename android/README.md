# EVA VPN для Android

Клиент на том же ядре sing-box, что и настольная версия.

## Состояние

Собирается в APK и устанавливается на телефон. Проверено здесь:

- проект собирается целиком (`gradle assembleDebug`), APK ~67 МБ;
- готовый APK разобран штатным `aapt2`: пакет, разрешения, точка входа
  и нативный код под arm64 на месте;
- генератор конфигурации прогнан на JVM и **каждая полученная конфигурация
  проверена настоящим ядром** командой `sing-box check` — семь вариантов,
  включая все поддерживаемые типы ключей и свои правила.

Чего здесь проверить нельзя: поведение на живом устройстве. Телефона у
сборочной машины нет, поэтому запуск туннеля, разрешение системы на VPN и
работа в фоне проверяются только вами.

## Сборка

Нужны инструменты (ставятся переносимо, без прав администратора):

```
~/android-build/
  jdk/        Temurin JDK 17
  go1.25/     Go 1.25.x  (на 1.27 сборка ядра падает, см. ниже)
  sdk/        Android SDK: platforms;android-35, build-tools;35.0.0,
              ndk;28.0.13004108
  gradle-8.9/ Gradle 8.9
  gopath/     сюда ставятся gomobile и gobind
  src/sing-box/  исходники sing-box v1.13.12
```

В пути к инструментам **не должно быть пробелов**: `sdkmanager` — пакетный
файл, он рвёт путь по пробелу, NDK и gomobile тоже этого не переживают.

Затем:

```bash
node scripts/build-libbox.mjs          # собрать ядро в libbox.aar
cd android && gradle assembleDebug     # собрать APK
```

APK появится в `app/build/outputs/apk/debug/`.

### Две ловушки, каждая стоит часа

**Версия Go.** Ядро собирается только на Go 1.25.x. На 1.27 сборка падает с
`undefined: json.SkipFunc`: библиотека `go-json-experiment/json` подменяет
себя стандартным `encoding/json/v2` по условию `goexperiment.jsonv2 && go1.25`,
а состав этого пакета в 1.27 уже другой. В CI самого sing-box стоит ~1.25.9.

**Ветка gomobile.** Нужен `github.com/sagernet/gomobile@v0.1.12`, а не
апстримный `golang.org/x/mobile`: апстримный не понимает, как sing-box
описывает интерфейс платформы. И собран он должен быть тем же Go, что и ядро.

## Проверки

```bash
node scripts/check-android-config.mjs
```

Прогоняет проверки на JVM и скармливает каждую полученную конфигурацию
настоящему `sing-box check`. Без этого об ошибке в генераторе мы узнавали бы
уже по молчащему туннелю на чужом телефоне.

## Чем отличается от настольной версии

**IPv6 не блокируется.** На компьютере мы его выключаем как частый канал
утечки настоящего адреса. У сотовых операторов сеть сплошь и рядом только на
IPv6 с NAT64 — запрет оставил бы телефон без интернета, и человек решил бы,
что сломался VPN.

**MTU 1400, а не 9000.** Девять тысяч имеют смысл на проводной сети; в
сотовой реальный размер пакета около 1400, и всё, что больше, режется.

**Раздельное туннелирование по пакетам, а не по именам файлов.** Путей к
`.exe` на Android нет; список приложений передаётся ядру при запуске, и
применяет его сама система через `VpnService`. Заодно исчезает проблема
регистра, из-за которой на Windows пришлось переходить на регулярные
выражения.

**strict_route выключен.** Маршрутами распоряжается система, а не ядро.

## Устройство

```
app/src/main/java/ai/theeva/vpn/
  core/        общая логика: разбор ключей, правила, конфигурация, хранилище
  bg/          служба туннеля: VpnService + интерфейс платформы для ядра
  ui/          оформление экранов
  *Activity.kt экраны: главный, ключи, правила, приложения
app/libs/      сюда кладётся собранный libbox.aar (в git не хранится)
```

Ключевое место — `bg/EvaVpnService.kt`. В нём сходятся три роли: системная
служба Android, интерфейс платформы для ядра и обработчик его событий. Там же
вызывается `protect()` для сокетов ядра: без этого соединение до сервера
уходит в туннель, который сам же этим соединением и живёт, и всё встаёт
намертво, не оставляя следов в журнале.

Списки адресов для готовых наборов правил (`core/RuleLists.kt`) порождаются
из настольного `src/main/rules.js`. Правьте их там и пересоздавайте файл,
иначе телефон и компьютер начнут вести себя по-разному.
