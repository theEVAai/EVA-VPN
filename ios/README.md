# EVA VPN для iPhone

Клиент на том же ядре sing-box, что и настольная версия и Android.

## Честно о состоянии

Исходный код полон: приложение, расширение туннеля, разбор ключей, система
правил, сборка конфигурации. **Но он ни разу не собирался.** Писался он на
Windows, а собрать проект для iPhone можно только на macOS: Xcode существует
только там, и библиотека ядра под Apple тоже собирается его инструментами.

Что из этого следует: первая сборка на Маке почти наверняка потребует
мелких правок — Xcode покажет их сразу и по одной. Логика при этом перенесена
с проверенных платформ: генератор конфигурации сверен с Android построчно по
набору полей (47 из 47 совпадают), а разбор ключей повторяет настольный.

Чего точно не хватает без вашего участия:

- **Платный аккаунт разработчика Apple.** Право `packet-tunnel-provider`
  бесплатному профилю не выдаётся. Без него приложение соберётся и запустится,
  но туннель не поднимется.
- **Настоящее устройство.** В симуляторе VPN не работает.

## Сборка

```bash
brew install xcodegen go
git clone --depth 1 --branch v1.13.12 https://github.com/SagerNet/sing-box.git ~/sing-box
EVA_SINGBOX_SRC=~/sing-box ./build.sh --open
```

Скрипт собирает `Libbox.xcframework` из исходников sing-box и порождает
проект Xcode из `project.yml`. Файл `.xcodeproj` в репозитории намеренно
не хранится: это машинный список с идентификаторами, который невозможно
писать и сливать руками.

Дальше в Xcode:

1. В обеих целях указать свою команду разработчика (Team).
2. Зарегистрировать группу приложений `group.ai.theeva.vpn` — без неё
   расширение туннеля не увидит ни ключей, ни правил, потому что это
   отдельный процесс.
3. Запустить на устройстве.

Версия Go должна быть 1.25.x. На 1.27 сборка падает с `undefined: json.SkipFunc` —
подробности в `scripts/build-libbox.mjs`.

## Чем отличается от настольной версии

**Раздельного туннелирования по программам нет, и не будет.** Apple не даёт
обычному приложению делить трафик по программам — такое доступно только
управлению корпоративными устройствами. Поэтому вместо списка `.exe` здесь
правила по адресам, и это не упрощение, а единственный доступный способ.

**IPv6 не блокируется.** На компьютере мы его выключаем как частый канал
утечки настоящего адреса. У сотовых операторов сеть сплошь и рядом только
на IPv6 с NAT64 — запрет оставил бы телефон без интернета.

**MTU 1400, а не 9000.** В сотовой сети пакеты больше этого режутся.

## Правила вместо списка программ

Три действия, больше человеку не нужно:

| Действие | Что происходит |
|---|---|
| Через VPN | Идёт через туннель, как всё остальное |
| Мимо VPN | Идёт напрямую через оператора, ваш настоящий адрес |
| Заблокировать | Не открывается вообще: соединение обрывается |

Человек вводит адрес, а приложение само определяет, что это, и пишет об этом
обычными словами **до** того, как правило будет добавлено:

```
example.com              → Домен example.com и все его поддомены
https://vpn.theeva.ai/x  → Домен vpn.theeva.ai и все его поддомены
10.0.0.0/8               → Диапазон адресов 10.0.0.0/8
443                      → Всё, что идёт на порт 443
tracker                  → Любой адрес, в котором встречается «tracker»
```

Так не нужно знать разницу между `DOMAIN-SUFFIX`, `DOMAIN-KEYWORD` и
`IP-CIDR`, как в Clash и Shadowrocket: приложение выбирает вид правила само,
а человек видит и проверяет этот выбор.

Плюс готовые наборы, включаемые тумблером: трекеры, российские сайты мимо
VPN, починка Kodik, торренты мимо VPN, App Store мимо VPN. Списки для них
порождаются из общего файла `src/main/rules.js`, поэтому на всех трёх
платформах они совпадают буква в букву.

## Устройство

```
Sources/Core/     общая логика: ключи, правила, конфигурация, хранилище
Sources/App/      приложение на SwiftUI
Sources/Tunnel/   расширение NetworkExtension — сам туннель
Resources/        Info.plist и права обеих целей
project.yml       описание проекта для XcodeGen
build.sh          сборка ядра и создание проекта
```

`Sources/Core` собирается в обе цели: приложение и расширение — разные
процессы, общего кода между ними иначе не будет.
