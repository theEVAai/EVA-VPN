# EVA VPN Windows 0.7.0 — маршруты по доменам

15 октября 2026. Android и iOS остаются на предыдущей версии; эта сборка для Windows.

## Как пользоваться

1. Добавить нужные ключи в «Ключи и подписки».
2. Открыть «Меню → Раздельное туннелирование → Домены».
3. Нажать «Добавить правило», вписать название и домены — по строкам или через запятую.
4. В «Куда направлять» выбрать Direct, Block, активный ключ или конкретный ключ из списка.
5. Сохранить. После настройки правил нажать «Применить» или подключить VPN заново.

Пример настройки под запрос владельца; страны выбираются из его собственных ключей:

| Домены | Выбранный ключ / действие |
| --- | --- |
| `endfield.gryphline.com` | Япония |
| `youtube.com`, `youtu.be`, `googlevideo.com`, `ytimg.com` | Нидерланды |
| `tiktok.com` | Польша |
| `example.org` | Direct |
| `blocked.example.org` | Block |

Домен Endfield соответствует [официальному сайту](https://endfield.gryphline.com/en-us/news/9574).
Пример не является полным списком служебных и CDN-доменов этих сервисов:
для входа, видео, загрузок и приложений могут понадобиться дополнительные домены.
Их можно добавить в то же правило, не меняя остальные маршруты.

## Поведение правил

- Домен включает сам адрес и его поддомены. `*.example.com` и `.example.com`
  приводятся к `example.com`. URL преобразуется в hostname; путь, query и порт
  не ограничивают правило. `https://example.com/page` действует на весь домен.
- IDN-домены приводятся к ASCII. IP-адреса и wildcard внутри имени не принимаются.
  Предпросмотр показывает, какие домены будут сохранены.
- Один домен нельзя записать в несколько групп. Для отдельного поддомена можно
  задать своё действие: `blocked.example.org` важнее `example.org`.
- Приоритет: перехват DNS и служебные ограничения → явные доменные правила →
  локальная сеть → исключения программ → наборы → режим программ → маршрут по умолчанию.
  В DNS действуют соответствующие доменные правила в том же порядке точности.
- Для дополнительного ключа создаётся независимый outbound в одном ядре sing-box,
  а не каскад и не отдельный TUN. DNS для выбранного домена использует отдельный
  резолвер через тот же outbound. Direct DNS идёт напрямую; Block возвращает NXDOMAIN.
- Подключения к сайту через недоступный выбранный ключ не переключаются автоматически
  на активный ключ или Direct. Если ключ удалён, его правила остаются и блокируют
  свои домены до ручного выбора нового ключа или выключения правила.
- Обновление подписки сохраняет ID/цвет по ссылке или совпавшему серверу;
  при ротации адреса/ключа используется уникальное сочетание имени и протокола.
  При неоднозначности привязка не переносится на случайный сервер.
- Правила и их переключатели сохраняются в существующих настройках приложения.
  Редактирование работающего клиента не разрывает соединение: требуется явное
  «Применить» или последующее подключение. Уже открытые потоки могут использовать
  прежний маршрут до переподключения; после него сайт может потребовать перезагрузку.
- Режим системного прокси охватывает только программы, которые используют прокси.
  В режиме TUN для определения имени используются sniffing и обратная DNS-карта.
  Независимый зашифрованный DNS браузера/приложения и скрытый hostname могут мешать
  определению домена; сопоставление произвольного HTTPS-пути не поддерживается.

Схема сверена с исходниками sing-box 1.13.12:
[domain rules](https://github.com/SagerNet/sing-box/blob/v1.13.12/route/rule/rule_item_domain.go),
[DNS reverse_mapping и структуры резолверов](https://github.com/SagerNet/sing-box/blob/v1.13.12/option/dns.go).
Работа с реальными ключами и сайтами в этой сессии не проверялась.

## Сборка и границы проверки

Упаковка: локальный electron-builder, `--win --publish never`, отдельный
каталог `dist/0.7.0`. Установщик и portable предназначены для ручной проверки владельцем.
Упаковка обоих файлов завершилась успешно. Готовые исполняемые файлы не запускались.

По действующей просьбе владельца тесты не запускались: ни приложение, ни sing-box,
ни VPN, ни сетевые запросы через его ключи. Не запускались также синтаксические,
визуальные и конфигурационные тесты. Проверка ограничена чтением и разбором кода;
успешная упаковка не подтверждает поведение приложения при запуске.
Активное соединение, маршруты и firewall не изменялись. Приложение не устанавливалось.
Публикация на GitHub выполняется штатным workflow `release` по тегу `v0.7.0`:
он собирает установщик и portable без запуска тестов. Исходники выпуска находятся
в ветке `codex/release-0.7.0`, поэтому проверки, настроенные на push в `main`,
для этой публикации не запускаются.
